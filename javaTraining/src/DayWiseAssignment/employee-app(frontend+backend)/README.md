# Employee Management System

A full-stack CRUD application to manage employee records, built with a **Spring Boot** REST API backend and an **Angular** frontend, backed by **MySQL**.

---

## 🧱 Tech Stack

**Backend**
- Java 21
- Spring Boot 3.5.3
- Spring Data JPA (Hibernate 6.6)
- MySQL 8.0
- Maven
- Apache Tomcat 10 (embedded)

**Frontend**
- Angular 19.2 (standalone components)
- Bootstrap 5.3
- RxJS

---

## ✨ Features

- Full CRUD operations on employee records (Create, Read, Update, Delete)
- Client-assigned employee IDs with duplicate-ID validation before creation
- Centralized exception handling — proper `404 Not Found` responses instead of raw stack traces
- CORS-enabled REST API for cross-origin frontend requests
- Bean validation on required fields (`name`, `desg`)
- Clean layered architecture (Controller → Service → Repository → Entity)

## ⚙️ Backend Setup

### Prerequisites
- JDK 21
- MySQL 8.x running locally
- Maven (or use the bundled Maven wrapper)

### 1. Configure the database

Create `src/main/resources/application.properties`:

```properties
spring.application.name=employee-app
server.port=8081

spring.datasource.url=jdbc:mysql://localhost:3306/empappdb
spring.datasource.username=root
spring.datasource.password=your_password
spring.datasource.driver-class-name=com.mysql.cj.jdbc.Driver

spring.jpa.hibernate.ddl-auto=update
spring.jpa.show-sql=true
spring.jpa.properties.hibernate.format_sql=true
spring.jpa.database-platform=org.hibernate.dialect.MySQLDialect
```

> The database `empappdb` will need to exist beforehand, or add `?createDatabaseIfNotExist=true` to the URL to have it created automatically.

### 2. Run the application

```bash
cd employee-app
./mvnw spring-boot:run
```

The API will start on **http://localhost:8081**.

### Employee Entity

```java
@Entity
@Table(name = "emp_Table")
public class Employee {
    @Id
    private Long id;          // client-assigned, not auto-generated

    @NotBlank(message = "Name is required")
    private String name;

    @NotBlank(message = "Designation is required")
    private String desg;
}
```

> **Note:** IDs are manually assigned by the client, not auto-generated by the database. The frontend checks for an existing ID before creating a new employee to avoid accidental overwrites.

## 🔌 API Endpoints

Base URL: `http://localhost:8081/api/employees`

| Method | Endpoint         | Description                  | Success | Error       |
|--------|------------------|-------------------------------|---------|-------------|
| GET    | `/api/employees`      | Get all employees        | 200     | —           |
| GET    | `/api/employees/{id}` | Get employee by ID       | 200     | 404         |
| POST   | `/api/employees`      | Create a new employee    | 201     | 400 (validation) |
| PUT    | `/api/employees/{id}` | Update an existing employee | 200 | 404         |
| DELETE | `/api/employees/{id}` | Delete an employee       | 204     | 404         |

**Sample request body (POST/PUT):**
```json
{
  "id": 101,
  "name": "Hitesh Patwal",
  "desg": "Software Engineer"
}
```

**Sample error response (404):**
```
Employee not found with id: 101
```

## 🔗 Connecting Frontend & Backend

1. Ensure the backend is running on `http://localhost:8081`.
2. Ensure `@CrossOrigin("*")` is present on `EmployeeController` to allow requests from the Angular dev server (`http://localhost:4200`).
3. Ensure `employee.service.ts`'s `BASE_URL` matches the backend's actual host, port, and route (`/api/employees`).
4. Start the backend first, then the frontend, then navigate to `http://localhost:4200`.

## 🐛 Common Issues & Fixes

| Symptom | Cause | Fix |
|---|---|---|
| CORS error in browser console | Missing `@CrossOrigin` on controller | Add `@CrossOrigin("*")` above `@RestController` |
| `Incorrect table definition; there can be only one auto column` | Existing table has a conflicting `AUTO_INCREMENT` column | Use a fresh table name via `@Table(name = "...")`, or manually alter the column |
| Add Employee doesn't navigate to the list page | Backend returns `500` instead of `404` for missing IDs | Add a `GlobalExceptionHandler` with `@RestControllerAdvice` |
| `Identifier ... must be manually assigned before calling 'persist()'` | `@GeneratedValue` removed from entity, but service still nulls the ID before saving | Remove `employee.setId(null)` in `addEmployee()` when using client-assigned IDs |
| Frontend calls fail silently / 404 on every request | `BASE_URL` port/route doesn't match the running backend | Confirm backend port (`server.port`) and `@RequestMapping` path match the Angular service |

---

## 📌 Notes

- Employee IDs are **client-assigned** (no `@GeneratedValue`), so uniqueness is enforced at the application layer, not the database's auto-increment.
- `spring.jpa.hibernate.ddl-auto=update` will not modify existing column constraints (e.g., removing `AUTO_INCREMENT`) — schema changes affecting existing columns require a manual `ALTER TABLE` or a fresh table.
